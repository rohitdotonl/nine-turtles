# 0135: A critique checklist for every change the reader sees

**In one line:** Twelve critique questions (from the owner's design field guide) every change the reader sees answers before its pull request; the full review checks them

*1 November 2026.*

**Decision.** The ten principles (decision 0134) become twelve questions,
adapted from the critique checklist in the owner's design field guide, in
`docs/DESIGN.md` → "Rules about the rules", rule 5. Every change the reader
sees answers them before its pull request, and the full second-agent
review checks them. A "no" is fixed, or written in the Exceptions log as a
deliberate break.

**Why.** The owner asked how the principles will actually steer an agent's
design decisions. Ranked principles settle conflicts; the feature checks
decide whether something should exist; the critique checklist checks how
each screen is made, in questions an agent can answer from a screenshot.
