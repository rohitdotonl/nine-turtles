# 19. Keyboard

*Part of the spec ([index](../SPEC.md)). `docs/DESIGN.md` takes precedence.*

**What it does**
- Every action works with standard keys (Tab, Enter, Escape) with a clearly visible focus outline. Letter keys are an extra, in this order, the key that matters most first in each group (decision 0180). Where it can, a row's name carries its letter, so it's easier to remember: **V**iew original, **I**nfo about this person, **R**efresh, **H**ighlight, **F**ull-screen.

  | Group | Key | Action | Row in the list |
  |---|---|---|---|
  | Reading | `j` / `k` | Next / previous article | Next / previous article |
  | | `w` | Write back to whoever wrote the open or selected article, when it's a person's (a publication has none, section 37) | Write back |
  | | `Enter` | Open the article | Open article |
  | | `s` | Star / unstar | Star / unstar |
  | | `h` | Highlight the words chosen (section 42) | Highlight chosen words |
  | | `n` | Write a note on the words chosen, or on the whole open article (section 42) | Add a note |
  | | `v` | View original | View original |
  | | `Space` / `Shift+Space` | Scroll the open article down / up one screen | Scroll down / up a screen |
  | | `+` / `-` | Text size while reading | Text size |
  | | `c` | Copy the open article's link | Copy link |
  | | `Esc` | Back / close | Back / close |
  | Go to: press G, then… | `g` then `u` / `s` / `a` | Go to Unread / Starred / All articles | Unread, Starred, All articles |
  | | `g` then `n` | Go to Notes | Notes |
  | | `g` then `,` | Go to Settings | Settings |
  | Getting around | `/` | Search | Search |
  | | `Shift+J` / `Shift+K` | Next / previous in the sidebar | Next / previous in the sidebar |
  | | `←` / `→` | Move the keyboard to the pane before / after: the sidebar, the list, the article (or their page) | Move between panes |
  | | `e` | The settings of the person or publication whose list you're in, a page of their own (decision 0267), or Edit folder in a folder's list | Their settings |
  | | `o` | Open or close the folder you're in, or the first folder of the person you're viewing, in the sidebar | Open / close this folder |
  | | `i` | About this person or publication (their page, section 36) | Info about this person |
  | | `f` | Full-screen reading (hide sidebar and list) | Full-screen reading |
  | | `a` | Add a person or publication | Add a person or publication |
  | Tidying up | `Shift+A` | Mark all as read | Mark all as read |
  | | `m` | Mark current item unread | Mark unread |
  | | `u` or `Command Z` (`Ctrl Z` off a Mac) | Undo | Undo |
  | | `r` | Show new articles | Refresh (show new articles) |
  | (not printed) | `?` | Opens this list; its Keys button's tooltip names it | |
  | (not printed) | `↑` / `↓` | In the sidebar, the row above / below; in the list, the article above / below; in the article, scrolling: keys everyone already expects | |
  | (not printed) | `Home` / `End` | First / last article in the list (End: the last one loaded so far): keys everyone already expects, so they need no row | |

- **Space** (decision 0103) moves the open article on by one screen, at once, never gliding, keeping a few lines of the last screen in view; `Shift+Space` moves it back. It works wherever the keyboard's place is (the article, its row in the list, a link in the sidebar) while an article is open, except on a control that takes Space itself (a button, a tick box, a switch, a menu, a field), where Space presses that control as always. At the end of the article it simply stops: it never opens the next one. With no article open, Space is the browser's own.
- **`o`** opens or closes, in the sidebar, the folder you're viewing (or the first folder of the person or publication you're viewing), so a folder `Shift+J` landed on can be opened from the keyboard. **`e`** opens the settings of the person or publication whose list you're in, a page of their own with the keyboard on its title and Name one Tab on (decision 0267), or Edit folder in a folder's list (the owner's core path, point 16, decision 0183); not in a search's results.
- **The arrow keys** (the owner's core path, point 17): `←` and `→` move the keyboard's place between the panes in view, left to right: the sidebar (onto the row you're in, else its first), the list (onto the chosen article, else the first) and the article or their page (onto its title). The pane you land in shows the keyboard's place: a row or an article rings, and a title, as every title, shows none, but the next arrow or Tab goes on from there. From outside every pane, either goes to the list; at either end, or on a phone, they're the browser's own; while reading full-screen they do nothing. `↑` and `↓` move inside the pane you're in: along the sidebar's rows (from a folder's open/close button, to the rows around it), along the list's articles as `j` / `k` do, or scrolling the article. Wherever the keyboard's place is, it shows its outline. In a field, an open menu, a row of choices, a slider, the pane's resizer, the podcast player and its bar, or a code block or table in the article that's wider than the page (where ← and → scroll it sideways), the arrows keep their usual job.
- **`i`** (decision 0163) opens the page of the person or publication whose list you're in; in any other list (a folder, Unread, search results), that of the chosen article's writer (decision 0214). The **Menu key** or **Shift+F10** on a row opens its own menu (section 6). **`c`** copies the open article's link to the original, as More › Copy link does, and the top bar says "Link copied.".
- Go to Unread and Mark all as read do nothing with Unread off (section 10), and the list leaves them out then.
- **`Shift+J` / `Shift+K`** (decisions 0110, 0180; "Next / previous in the sidebar") go to the next / previous row in the sidebar, top to bottom as it shows them: Unread, Starred, Notes and All articles (those that show), then folders A to Z (Everyone you follow, which isn't a list of articles, is passed over; decision 0266), each with what's in it while it's open, then People, then Publications. A folder opens its combined list, so you can jump to a folder and read everyone in it. A folded folder's feeds are passed over, so the next press goes to the next folder; `o` opens it. `Enter` only opens an article. A feed in two folders counts once, where it's first listed. At either end nothing happens. From a list that isn't in the sidebar (Unread, opened by its address while it's off), `Shift+J` goes to the first row and `Shift+K` does nothing. On a phone every folder counts as open. They work from a list, not from Settings or a sheet.
- **A key that needs an article, with none chosen,** says what to do (decision 0230): `s`, `m`, `w` and `n` on a list with no article chosen say "Choose an article first. j chooses the first one." in the list's note, as a passing line.
- **A key with nothing to do says why** (decision 0229): `j` on the last article, `k` (or `↑`) on the first, says so in the list's note ("That's the first article here.", "That's the last article here.", or "That's the last one so far. More load as you scroll down." while older ones are still to load); `u` with nothing to undo says "Nothing to undo." These are passing lines: they never take away the last action's Undo (`u` still undoes it) or cover a failed save's line.
- **`Home` / `End`** (decision 0110) choose the first / last article listed and show it, as `j` / `k` do. `End` goes to the last article loaded so far; it never loads more itself. They work only while a list is in view: in the open article (the keyboard anywhere in it, or the list hidden, or on a phone) they scroll the article to its top or end as usual, and on a page that isn't a list (Settings, Everyone you follow, Muted, Readers) they scroll that page. On a field, a row of choices or a menu, Home and End stay that control's own.
- **`g` then `,`** opens Settings, from anywhere outside a field.
- **Every reader has the same keys** (decision 0170). Choosing keys of your own (decision 0110) was removed in step 5 of the owner's review, with Settings › Keyboard; every shortcut stays. The `?` list's foot has only **Help**, which opens the website's "Every keyboard key" page in a new tab (section 40).
- **One list of keys** (decision 0103): each shortcut is written down once, with its keys and what each does, and both the keys that work and the cheat sheet come from it, as do tooltips and menus. An automatic check presses every key a keyboard can type and fails if one does something the table doesn't hold, or if a key doesn't do what its row says. The list prints every key in the table except `?`, Home, End, `↑` / `↓` and `=` (which stands in for `+`).
- **Keys**, an icon and its word at the foot of the sidebar, opens the shortcut list (screen readers hear "Keys (keyboard shortcuts)"; its tooltip says "Keyboard shortcuts (?)"), and so does `?` anywhere (decision 0062). While the list is open the button sits on a faint ink tile (never the accent, since it's a button), and screen readers hear that it opens a dialog and whether it's open (decision 0054). There's no hint under the list, whether the sidebar shows or not.
- **One welcome tip, once** (decision 0062): on a screen with a keyboard, the first time the reading area shows its quiet line with articles in the list, a quiet line hangs under it in small muted type: "Press J to read. Press W to write back.", the keys as key caps (decision 0180): reading and writing back are the whole idea. Once you open any article (by click or key) or the shortcut list, it never shows again on that device. Touch screens never show it. On a phone the keyboard icon isn't shown; `?` still opens the list from a hardware keyboard.
- The `?` list groups the shortcuts by what you're doing, what each does on the left and its keys on the right, in two columns on a window at least 768px wide: Reading, then Go to: press G, then…; Getting around, then Tidying up (decision 0180). Its title is in the same serif as every other title; each group's heading is in the text color, semibold, larger than the rows and smaller than the title, with more room above it than between rows. Rows are parted by spacing alone, with no line under them. `G then` is said once, in the heading **Go to: press G, then…**; its rows print only the second key, and screen readers hear both. No row wraps. It's never taller than 720px and stays at least 48px clear of the window's top and foot, and at 1280 × 800 the whole list fits without scrolling. On a phone it fills the screen, as every sheet does there, in one column. It has an X to close it (or Escape); it opens with the keyboard on its title rather than the X, and the title shows no ring, since it can't be pressed (the X and the list ring as soon as Tab reaches them). When it does scroll, a faint line shows under the title once the list has moved, and one near its foot while more lies below. Until a shortcut's feature exists, it isn't listed, and the key does nothing.
- **Every key looks the same, on every computer** (decision 0180): letters in capitals and Shift as the word, never ⇧. In the list and the welcome tip keys are key caps, and Shift is a cap of its own: `Shift+A` shows [Shift] [A]. Key caps are only for the list and the welcome tip. Menus (the More menus and the Highlight menu) print a key in plain grey capitals at the row's end, as desktop menus do: "Shift A", "M", "H". A tooltip says it in words: "Mark all as read (Shift A)", "Write back to Tomas (W)", "Star (S)" or "Unstar (S)". Screen readers hear "Shift A". The - key prints as a true minus sign.
- The keyboard's place is shown by a 2px outline in the text color (never the accent, which marks what's unread and what a search found). Rows draw it just inside their rounded edge, in a slightly softened text color, so it never reaches over the hairlines between rows; the selected row keeps its pill. A text field in use rings the same softened text color, 2px, 1px clear of the field, its own edge stepping aside, at 3 : 1 or more against the field and whatever it sits on in every theme (decision 0055). A title that receives the place (a screen opening, a sheet, an opened article, or a key such as `g` then `a`), so screen readers start there, shows no ring, even after a key: it can't be pressed, and the next Tab lands on a real control, which rings (decisions 0042, 0047; since 27 October 2026 for every title).
- **Skip to articles** is the first thing on the app's screen to take the keyboard while a list of articles shows (the keyboard starts later, on the list's title, so it's reached by Tab from the browser's own address bar and controls): hidden until the keyboard reaches it, then a small label at the top left with its ring. Enter takes the keyboard past the sidebar to the chosen article in the list, or the first (with none, to the list's title).
- A tooltip names its button's key after its name, in brackets, as a capital letter, the same way the key caps print it: "Star (S)", "Add a person or publication (A)", "Info about Jim (I)" (decision 0064).
- **Command Z** (Ctrl Z off a Mac) undoes, as `u` does, as in every other app (decision 0231): the one shortcut with Command or Ctrl. It works wherever `u` does, and never while typing in a field, where it stays the field's own undo; Command Shift Z, Option and Ctrl together with Command do nothing. The `?` list prints Undo's keys as "U or Command Z" ("or", not "/", because both do the same thing), and the Undo button in the list's note says it in its tooltip: "Undo (U or Command Z)". Every other key with Command or Ctrl stays the browser's.
- Shortcuts don't fire while you're typing in a field, nor while a word is being composed (Chinese, Japanese and the like). Caps Lock doesn't change them: with it on, `a` is still `a`, and Shift+A still Shift+A.
- Podcasts add no keys (decision 0113): Space still scrolls the article, and the player's controls answer to Enter, Space and the arrow keys only while the keyboard is on them (section 35).

**How to check it**
1. Unplug the mouse (or don't touch it). Using only Tab, Enter and Escape, add a feed, read an article, star it and search. You can always see where the focus is. Reload: the keyboard is on the list's title; click the browser's address bar and press Tab: "Skip to articles" shows, and Enter on it lands on an article.
2. Try each vim key from the table.
3. Press `?` at 1280 × 800: two columns, nothing scrolls, nothing wraps, no field to type in, and no search filters. Escape closes it.
4. Press `Shift+H`, `[`, `]`, `\`, `Shift+E`, `Shift+N` and `g` then `f` in a list: nothing happens (decision 0180).
5. Open a long article and press Space a few times: it moves down a screen each time and stops at the end, staying on the same article. `Shift+Space` moves it back up. With the keyboard on the article's More button, Space opens its menu instead.
6. Press `j` to choose an article, then `Enter`: the keyboard's place moves into the article.
7. Press `Shift+A` in a feed: what's listed turns grey and the note says "Marked … articles as read." with Undo. Press `u`: they're unread again. Do it again and press Command Z (Ctrl Z off a Mac): the same. In the search field, Command Z undoes typing only. `Shift+O` does nothing (decision 0171).
8. With an article open, press `c`: "Link copied." shows in the top bar, and pasting gives the publisher's address.
9. In a feed inside a folder, press `o`: the folder closes in the sidebar; again, it opens. Press `i`: their page opens. Back in their list, press `e`: their settings open, and Tab goes to Name; Escape goes to their page, and again to their list; in a folder's list, `e` opens Edit folder.
10. In Unread, press `Shift+J`: the next list in the sidebar opens; keep pressing and it goes on to the folders (each opens its combined list); `Shift+K` goes back. With a folder folded, its people are passed over and the next press goes to the next folder. In a feed, `End` chooses the last article loaded and `Home` the first. Open an article and press `End`: it scrolls to the article's end, and the same article stays chosen. On Settings, `End` scrolls the page. `g` then `,` opens Settings.
11. Press `?`: its foot has only Help, and Settings has no Keyboard page.
12. With an article open on a wide window, press `←`: the keyboard is on the list's chosen article; `←` again, on your row in the sidebar; `↓` and `↑` go along the sidebar's rows; `→` twice comes back to the article, where `↓` scrolls it. In the search field, `←` and `→` move through the words as always.
